> - A feature is marked with its calling path **ONLY** when an active worker or HTTP route in `backend/src/` actually imports and calls the implementation. Anything not called by a worker or route is explicitly marked **`NOT WIRED`**.
> - A feature is marked **Proven by test** ONLY when a live, database-backed test connects to a real MongoDB replica set (`MongoMemoryReplSet`), executes the production code path, and asserts database state, scheduler behavior, or adapter call counts.

### Production Deployment & MongoDB Assumptions

1. **MongoDB Replica Set:**
   - Production deployment requires a MongoDB 6.0+ replica set (single node or multi-node with primary-secondary) to support multi-document ACID transactions utilized in dispatch execution, capacity reservation, and webhook reconciliation.
   - WiredTiger storage engine must have write concern `w: "majority"` enabled for transaction durability.
2. **Index Initialization:**
   - Run `npx tsx backend/src/scripts/ensureIndexes.ts` during pre-deployment orchestration before worker processes spin up to ensure all compound unique indexes and TTL indexes are physically built.
3. **Background Worker Topology:**
   - Workers (`backend/src/workers/planner.ts`, `backend/src/workers/executor.ts`, `backend/src/workers/events.ts`, `backend/src/workers/sweeper.ts`) should be run under process supervision (systemd or Kubernetes Deployment) with `AUTORUN_CYCLE=true` and distinct worker heartbeat monitors.
   - Multi-tenant event worker (`events.ts`) automatically discovers all provisioned tenants and fairly balances round-robin batches across them; tenant-specific worker pinning is not required.
4. **Environment Configuration:**
   - Production environment must have `NODE_ENV=production`, valid `JWT_SECRET` (minimum 32 characters), and `APP_ENCRYPTION_KEY` (32 bytes / 64 hex characters) configured for AES-256-GCM phone encryption at rest. Seed scripts are strictly forbidden from running in production.
